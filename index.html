Research architecture · seL4 substrate

Expose meaning, not machines.

Describe what the system means, what is allowed, and when it must happen. Compile that description into capabilities, resources, scheduling, and bounded execution paths.

Read the architecture See what actually exists
Semantics above. Enforcement below. A user thinks in refrigerators, motors, rooms, services, and deadlines. The kernel sees capabilities, endpoints, address spaces, scheduling contexts, interrupts, and memory. The research problem is the planner/compiler between those worlds.

02 / SYSTEM SHAPE

Semantic requirements, sibling workloads, verified installation

The target is a responsibility graph, not a numbered call stack. Invocation/action and Streaming are sibling workload planes; real-time, authority and provenance cut across them.

03 / SEMANTIC OBJECTS

Objects carry domain meaning

Instead of asking software to reconstruct intent from generic machine interfaces, the semantic layer names the entity, operation, authority, relation, and temporal contract directly.

Object

Refrigerator#17 is a stable semantic identity with properties, methods, streams, relations, and policy references.

Authority

Rights are expressed at the semantic level first: who may invoke which operation, under which constraints.

Temporal contract

Deadline, period/minimum inter-arrival time, jitter tolerance, criticality and blocking constraints are semantic requirements. Numeric scheduler priority/budget/period belong to the implementation plan.

08 / DO NOT COLLAPSE

Workloads and cross-cutting semantics are different axes

Invocation and Streaming describe workload shape. Provenance/causality and Real-Time describe properties that may apply across those workloads; they are not two more sibling runtimes.

Invocation / Action

Finite semantic action: turnOff(), deploy(version), setTemperature(4).

Streaming

Continuous/high-rate data: telemetry, CPU metrics, cameras, events, sensor time series.

Provenance / Causality

Which source, activity, subject and derivation produced current state; time fields support but do not define provenance.

Real-Time

A cross-cutting temporal contract: by when work must complete and under which clock, resource, blocking, WCET and scheduling assumptions.

09 / WHY seL4

A precise lower authority substrate

seL4 provides capability-based kernel mechanisms, isolation, IPC, and strong machine-checked verification results for specific kernel configurations. Those proofs do not automatically verify this project's planner, object model, runtimes, drivers, gateway, or deployment.

Domain meaning

Refrigerator · Motor · Server · ownership · temperature · deploy · emergency stop

compile → verify → install

Kernel mechanisms

capabilities · endpoints · threads · address spaces · memory objects · notifications · IPC · scheduling contexts

Verification boundary: Verified properties of seL4 ≠ verified Semantic Infrastructure OS.
