Architecture

System intent is compiled, not merely interpreted.

The target is a semantic operating environment whose upper layers describe objects, authority, relations, and temporal requirements while lower layers enforce a concrete capability/resource/scheduling topology.

A stratified graph, not a linear stack

The repository already treats its L0–L6 model as responsibility strata rather than a mandatory call chain. The site extends the target architecture by making deadline-sensitive execution a first-class sibling plane, while preserving the repository's key invariant that transaction and streaming are siblings.

Architecture ≠ implementation. A box on this page means “part of the target model”, not “already built”. See Status for evidence-backed implementation state.

Planner / Policy Compiler

The planner is the architectural hinge between domain meaning and kernel mechanisms. Its input can include semantic intent, authority, temporal contracts, criticality, placement/resource constraints, and lifecycle state. Its output is an enforceable system plan: capabilities, IPC topology, scheduling configuration, resource allocation, memory reservations, and chosen execution paths.

This is deliberately stronger than “put an ACL and UI over a conventional process model”. The research question is how much high-level authority and timing intent can be compiled into structure, and which constraints must remain runtime checks.

Sibling execution fabrics

PlaneOwnsDoes not mean
TransactionFinite semantic actions, result/commit/failure semantics, effectful dispatch.Continuous telemetry.
StreamingContinuous/high-rate data, fan-out, ordering, retention, sampling/backpressure policy.Hard deadline guarantee.
Real-TimeDeadline-sensitive paths, temporal contracts, resource/scheduling assumptions, admission and bounded execution.“Fast” or “online”.

Planning time vs deadline-critical runtime

Strong temporal guarantees become more plausible when expensive semantic reasoning is moved out of the critical path. Planning may resolve policy, construct topology, reserve resources, and install IPC/scheduling configuration. Runtime then follows pre-authorized/precomputed routes with bounded operations under stated assumptions.

Not everything must be static. The architectural claim is narrower: operations that require strong temporal guarantees should minimize dynamic graph queries, allocation, topology construction, and policy interpretation on their critical path.

Object Supervisor

The Object Supervisor is a responsibility area for object identity, class/schema metadata, lifecycle, relations, properties, method metadata, bindings/discovery, and references to policy or temporal contracts. Exact ownership boundaries remain research unless and until executable components establish them.
